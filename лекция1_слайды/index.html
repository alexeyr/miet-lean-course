Установка Lean в VS Code или VSCodium

  1. Установите VS Code и расширение Lean 4. Можно выбрать VSCodium и установить то же расширение из Open VSX.

  2. Скачайте репозиторий курса через Code → Download ZIP и распакуйте архив (или клонируйте репозиторий). Через File → Open Folder откройте папку с lakefile.toml.

  3. Откройте Лекция1.lean. Для установки Lean выберите в меню ∀ пункт Documentation → Show Setup Guide.

  4. В терминале редактора выполните команду lake exe cache get с аргументами, указанными в начале Лекция1.lean.

Пока идёт загрузка, можно работать в Lean Playground. Инструкция по установке

Выражения, типы и универсумы

Запись e : T читается «выражение e имеет тип T». Например, (2 : Nat) обозначает число 2 типа Nat.

Типы тоже являются выражениями. Какой тип у самого Nat?

#checkNat : Type Nat
Nat : Type

Nat : Type

#checkType : Type 1 Type
Type : Type 1

Type : Type 1

Универсум — это тип, элементами которого являются типы. Например, Nat и Int принадлежат универсуму Type. Сам Type принадлежит следующему универсуму Type 1.

Вычитание и типы операндов

Какой тип и какое значение получит каждое выражение?

#eval-5 (2 : Int) - 7
-5

-5 : Int

Тип первого операнда задаёт тип второго: здесь 7 имеет тип Int.

#eval0 2 - 7
0

0 : Nat

Для записей вроде 2 и 7 Lean по умолчанию выбирает Nat, если их тип не задан контекстом. В натуральных числах вычитание ограничено снизу нулём.

Что произойдёт, если у операндов разные типы?

#eval-5 (2 : Nat) - (7 : Int)
-5

-5 : Int

Приведение типов

Как Lean вычитает целое число из натурального?

#check↑2 - 7 : ℤ (2 : Nat) - (7 : Int)
↑2 - 7 : ℤ

↑2 - 7 : ℤ

Знак ↑ показывает, где Lean вставил приведение типов: он преобразовал натуральное число 2 в целое. Вычитание даёт результат типа Int, который mathlib обозначает ℤ.

В выражении (2 : Int) - 7 литерал 7 сразу получает тип Int из контекста.

Наберите сокращение и нажмите пробел: \N для ℕ, \Z для ℤ, \coe для ↑. Полный список в VS Code: Ctrl+Shift+P → Show Unicode Input Abbreviations. См. также таблицу на GitHub.

Определение функции

def addOne (n : Nat) : Nat := n + 1 #eval5 addOne 4
5

def вводит имя. В скобках стоят имя параметра и его тип. После скобок указан тип результата, после := записано тело.

При вызове addOne 4 параметр получает значение 4, и команда выдаёт 5.

Применение и скобки

def square (n : Nat) : Nat := n * n #eval10 square 3 + 1
10
#eval16 square (3 + 1)
16
#eval81 square (square 3)
81

Применение функции связывает сильнее, чем сложение. Запись square 3 + 1 означает (square 3) + 1.

Первое значение равно 10.

Во второй строке сначала вычисляется сумма, поэтому результат равен 16.

Что нужно вычислить первым в последней строке? Каким будет окончательный ответ?

Получим 9, затем 81.

Функция как аргумент

def twiceNat (f : Nat → Nat) (x : Nat) : Nat := f (f x) #checktwiceNat addOne : ℕ → ℕ twiceNat addOne
twiceNat addOne : ℕ → ℕ
#eval5 twiceNat addOne 3
5

Тип Nat → Nat описывает функцию с одним натуральным аргументом и натуральным результатом. Для ввода стрелки используйте \to.

После передачи addOne остаётся функция типа Nat → Nat.

Применив её к 3, получим 5.

Функция без имени

#eval12 twiceNat (fun n => n * 2) 3
12
#eval15 twiceNat (fun n => n + n + 1) 3
15

В выражении fun n => n * 2 слева от => записан параметр, справа — результат. Тип параметра здесь известен из типа twiceNat.

В первом примере промежуточное значение равно 6, окончательное — 12. Найдите оба значения во втором примере.

Получим 7, затем 15.

Какой тип нужен для двукратного применения?

def twice {α : Type} (f : α → α) (x : α) : α := f (f x) #eval12 twice addOne 10
12
#evaltrue twice (fun b => !b) true
true

α : Type — произвольный тип (\alpha для α). Тип f : α → α позволяет снова передать результат функции на вход.

Фигурные скобки объявляют неявный параметр.

В первом вызове Lean подставляет Nat и получает 12.

Во втором — Bool и получает true.

Укажем тип по имени:

#eval12 twice (α := Nat) addOne 10
12

12

Что именно проверяет Lean?

#evaltrue twice addOne 3 = 5
true

  • #eval проверяет равенство вычислением и выводит true.

#checktwice addOne 3 = 5 : Prop twice addOne 3 = 5
twice addOne 3 = 5 : Prop

  • #check сообщает, что равенство имеет тип Prop. Тип Prop имеют и ложные утверждения.

example : twice addOne 3 = 5 := by⊢ twice addOne 3 = 5 rflAll goals completed! 🐙 theorem twice_addOne_3 : twice addOne 3 = 5 := by⊢ twice addOne 3 = 5 rflAll goals completed! 🐙

  • Обе записи требуют доказательства. example анонимен, а theorem даёт теореме имя. В следующих доказательствах можно сослаться на twice_addOne_3.

Из чего состоит доказательство

example (n : Nat) : addOne n = n + 1 := byn:ℕ⊢ addOne n = n + 1 rflAll goals completed! 🐙

Параметр n произволен. За двоеточием после параметра стоит утверждение. Справа от := нужно предъявить его доказательство.

by открывает блок тактик. Тактика rfl закрывает равенство, если обе стороны совпадают с точностью до вычисления. Здесь достаточно раскрыть определение addOne.

Читаем цель в InfoView

exampledeclaration uses `sorry` (n : Nat) : addOne n = n + 1 := byn:ℕ⊢ addOne n = n + 1 sorryAll goals completed! 🐙

Поставьте курсор перед тактикой. Над знаком ⊢ видны данные и гипотезы, после него — цель.

n : Nat

⊢ addOne n = n + 1

sorry оставляет пропуск в доказательстве. Lean принимает объявление с предупреждением declaration uses 'sorry' и продолжает проверять файл.

example (n : Nat) : addOne n = n + 1 := byn:ℕ⊢ addOne n = n + 1 rflAll goals completed! 🐙

Замените sorry на rfl. Раскрытие addOne доказывает равенство. После этого шага цель закрыта, а предупреждение исчезает.

От вычисления к общему утверждению

example {α : Type} (f : α → α) (x : α) : twice f x = f (f x) := byα:Typef:α → αx:α⊢ twice f x = f (f x) rflAll goals completed! 🐙

Раскройте twice в левой части. По обе стороны останется f (f x), даже когда значения f и x неизвестны.

Как выбор α определяет типы f и x? Почему одно и то же доказательство rfl подходит для любых α, f и x?

Разбираем неудачную попытку

Замените правую часть предыдущего утверждения на f x. После раскрытия определения тактике пришлось бы доказать

⊢ f (f x) = f x

Проверьте кандидата в контрпримеры.

#eval5 twice addOne 3
5
#eval4 addOne 3
4

Первое вычисление даёт 5.

Второе даёт 4. Здесь ошибка в самом утверждении. Верните исходную правую часть, прежде чем двигаться дальше.

Когда утверждение верно, а шаг не проходит

example (a b : Nat) : a + b = b + a := bya:ℕb:ℕ⊢ a + b = b + a rfla:ℕb:ℕ⊢ a + b = b + aTactic `rfl` failed: The left-hand side a + b is not definitionally equal to the right-hand side b + a a b:ℕ⊢ a + b = b + a

rfl закрывает цель, когда обе стороны совпадают после вычисления. При произвольных a и b выражения a + b и b + a остаются разными.

example (a b : Nat) : a + b = b + a := bya:ℕb:ℕ⊢ a + b = b + a exact Nat.add_comm a bAll goals completed! 🐙

Теорема о коммутативности даёт Nat.add_comm a b типа a + b = b + a. Тактика exact закрывает цель этим доказательством.

Как переписать выражение с помощью rw?

example (a b : ℝ) : (a + b)^2 = a^2 + 2*a*b + b^2 := bya:ℝb:ℝ⊢ (a + b) ^ 2 = a ^ 2 + 2 * a * b + b ^ 2 rw [pow_twoa:ℝb:ℝ⊢ (a + b) * (a + b) = a ^ 2 + 2 * a * b + b ^ 2]a:ℝb:ℝ⊢ (a + b) * (a + b) = a ^ 2 + 2 * a * b + b ^ 2 rw [add_mul,a:ℝb:ℝ⊢ a * (a + b) + b * (a + b) = a ^ 2 + 2 * a * b + b ^ 2 mul_add,a:ℝb:ℝ⊢ a * a + a * b + b * (a + b) = a ^ 2 + 2 * a * b + b ^ 2 mul_add,a:ℝb:ℝ⊢ a * a + a * b + (b * a + b * b) = a ^ 2 + 2 * a * b + b ^ 2 mul_comm b a,a:ℝb:ℝ⊢ a * a + a * b + (a * b + b * b) = a ^ 2 + 2 * a * b + b ^ 2 pow_two,a:ℝb:ℝ⊢ a * a + a * b + (a * b + b * b) = a * a + 2 * a * b + b ^ 2 pow_two,a:ℝb:ℝ⊢ a * a + a * b + (a * b + b * b) = a * a + 2 * a * b + b * b two_mul,a:ℝb:ℝ⊢ a * a + a * b + (a * b + b * b) = a * a + (a + a) * b + b * b add_mul,a:ℝb:ℝ⊢ a * a + a * b + (a * b + b * b) = a * a + (a * b + a * b) + b * b ← add_assoc,a:ℝb:ℝ⊢ a * a + a * b + a * b + b * b = a * a + (a * b + a * b) + b * b add_assoc (a * a)a:ℝb:ℝ⊢ a * a + (a * b + a * b) + b * b = a * a + (a * b + a * b) + b * b]All goals completed! 🐙
theorem pow_two (x : ℝ) : x ^ 2 = x * x

Какую степень раскроет pow_two? Щёлкните по первой тактике rw, чтобы увидеть цель после этой замены.

a b : ℝ
⊢ (a + b) * (a + b) = a ^ 2 + 2 * a * b + b ^ 2

Дальше rw применяет равенства по порядку. Стрелка ← меняет направление замены.

Какое переписывание превращает ba в ab?

Как не перечислять все равенства?

example (a b : ℝ) : (a + b)^2 = a^2 + 2*a*b + b^2 := bya:ℝb:ℝ⊢ (a + b) ^ 2 = a ^ 2 + 2 * a * b + b ^ 2 ringAll goals completed! 🐙

При раскрытии квадрата получаем a^2+ab+ba+b^2. Коммутативность даёт ba=ab. Тактика ring приводит обе стороны полиномиального равенства к общей нормальной форме и строит доказательство, которое проверяет ядро Lean.

Верна ли эта формула для матриц A и B типа Matrix (Fin 2) (Fin 2) ℝ?

Fin 2 — тип с двумя значениями: 0 и 1. Первый Fin 2 задаёт индексы строк, второй — столбцов. Получается вещественная матрица 2\times2.

Самостоятельно: два способа прибавить четыре

def addTwo (n : Nat) : Nat := n + 2

  1. Вычислите twice addTwo 5. Сформулируйте, чему равно twice addTwo n для произвольного n : Nat, и докажите это с помощью rfl.

  2. Для произвольного x : ℝ запишите равенство (x+2)+2=x+4 и выберите тактику. Объясните, откуда взялась четвёрка.

#eval9 twice addTwo 5
9

Результат — 9.

Проверяем решения

example (n : Nat) : twice addTwo n = (n + 2) + 2 := byn:ℕ⊢ twice addTwo n = n + 2 + 2 rflAll goals completed! 🐙 example (x : ℝ) : (x + 2) + 2 = x + 4 := byx:ℝ⊢ x + 2 + 2 = x + 4 ringAll goals completed! 🐙

В первом случае раскрываются два определения: twice и addTwo. Во втором приводятся подобные слагаемые.
